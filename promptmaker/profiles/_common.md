# 공통 규칙 (모든 모델)

좋은 프롬프트의 기본 구성. 모델 프로필보다 우선순위가 낮다 — 모델 프로필과 충돌하면 모델 프로필을 따른다.

1. **목표(무엇을)와 의도(왜)를 분리해 명시한다.** 사용자가 왜 이걸 원하는지 원문에서 유추 가능하면 한 문장으로 적는다.
2. **범위와 경계를 명시한다.** 무엇을 건드리고 무엇을 건드리지 말아야 하는지. 원문에 없으면 합리적 기본값을 정하고 [가정]으로 표시한다.
3. **완료 기준을 명시한다.** "다 됐다"를 어떻게 확인하는지 (테스트 통과, 동작 확인 방법 등).
4. **결과물 형태를 명시한다.** 코드 수정인지, 분석 보고인지, 계획인지.
5. **원문에 없는 사실을 지어내지 않는다.** 파일명, 기술 스택, 에러 내용을 모르면 "먼저 ~를 확인하고"처럼 조사 지시로 바꾸거나 [가정: ...]으로 표시한다.
6. **사용자의 언어를 유지한다.** 한국어 원문이면 한국어로 재작성한다.
7. **여러 요청이 섞여 있으면 우선순위를 매겨 분리한다.** 순차 작업으로 정리하거나, 별개 작업임을 명시한다.
8. **문제 서술과 수정 요청을 구분한다.** 사용자가 문제를 설명만 하는 것인지 수정을 원하는 것인지 불명확하면, 원문의 뉘앙스에 맞게 하나로 정하고 [가정]으로 표시한다.
